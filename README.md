# ArduiDOOM - Mini DOOM for Arduino UNO R4 WiFi

A retro first-person shooter running on an **Arduino UNO R4 WiFi** with a 4" color TFT display, controlled by an **iPhone used as a wireless gamepad** over Bluetooth Low Energy.

The 3D view is rendered in real time on the Arduino using **raycasting**, the technique behind *Wolfenstein 3D*, the ancestor of DOOM. The iPhone app provides a touch joystick, a fire button and haptic feedback.

## Features

- **Real-time 3D rendering** on the Arduino: textured-color walls, distance shading, crosshair
- **6 demons** hidden in the maze: they spot you when they have line of sight, chase you and attack at close range
- **Shooting**: aim with the crosshair, two hits per demon, white flash on hit
- **HUD** with health, remaining enemies, weapon with muzzle flash, Bluetooth status and a live minimap
- **Game over and victory screens**, press FIRE to play again
- **iPhone gamepad**: virtual joystick, fire button with auto-fire, landscape layout
- **Haptic feedback** on the iPhone when you shoot, hit or kill a demon, take damage, die or win
- **Partial redraw engine**: only the parts of each column that change are sent to the display, to get the most out of the SPI bus

## Hardware

- Arduino UNO R4 WiFi
- 4.0" SPI TFT display, 480×320, **ST7796S** or **ILI9488** controller
- Jumper wires
- An iPhone running iOS 17 or later

### Wiring

| Display | Arduino UNO R4 WiFi |
|---|---|
| VCC | 5V |
| GND | GND |
| CS | D10 |
| RESET | D8 |
| DC / RS | D9 |
| SDI / MOSI | D11 |
| SCK | D13 |
| LED / BL | 3.3V |
| SDO / MISO | not connected |

The touch pins (`T_CLK`, `T_CS`, `T_DIN`, `T_DO`, `T_IRQ`) are not used.

> **Warning:** the UNO R4 uses **5V logic**. Some TFT modules accept 5V on VCC but only **3.3V on their data pins**. If your module's documentation says so, use a level shifter (for example a 74HC4050 or TXS0108E) on CS, RESET, DC, SDI and SCK.

## Arduino setup

1. Install the [Arduino IDE](https://www.arduino.cc/en/software) 2.x.
2. Install the **Arduino UNO R4 Boards** package (Tools → Board → Boards Manager).
3. Install these libraries (Tools → Manage Libraries):
   - `ArduinoBLE`
   - `GFX Library for Arduino` by Moon On Our Nation
4. Open `arduino/mini_doom/mini_doom.ino` and adjust the display settings at the top if needed:

   ```cpp
   #define ECRAN_ILI9488 0      // 0 = ST7796S, 1 = ILI9488
   #define ROTATION      1      // 1 = landscape, 3 = landscape flipped
   #define COULEURS_IPS  false  // true if colors look inverted
   ```

5. Select **Arduino UNO R4 WiFi** and upload. The "MINI DOOM" title screen appears, then the game.

## iOS setup

The repository contains the Swift source files only. To build the app:

1. In Xcode, choose **File → New → Project → iOS → App**, with **SwiftUI** and **Swift**.
2. Delete the `...App.swift` and `ContentView.swift` files generated by Xcode.
3. Drag the two files from `ios/` into the project, with **Copy items if needed** checked.
4. In the **Info** tab, add `NSBluetoothAlwaysUsageDescription` (Privacy - Bluetooth Always Usage Description) with a non-empty description.
5. In **General → Deployment Info**, keep only **Landscape Left** and **Landscape Right**.
6. Run the app on a **physical iPhone**. The simulator has no Bluetooth.

The app connects to the Arduino automatically. The status dot turns green when the gamepad is connected.

## How it works

### Rendering

For each of the 120 screen columns, the Arduino casts a ray through the map grid with a DDA algorithm until it hits a wall. The wall's distance gives its height on screen, and its color is darkened with distance. Demons are drawn as scaled 16×16 sprites, with a depth buffer so walls correctly hide them.

To keep the frame rate up, the engine remembers each column from the previous frame and only redraws the segments that changed. When nothing moves, nothing is redrawn.

### Bluetooth protocol

The Arduino acts as a BLE peripheral named **Mini Doom**.

| Characteristic | UUID | Direction | Format |
|---|---|---|---|
| Gamepad | `D00D0001-1F2E-4A3B-8C7D-6E5F4A3B2C1D` | iPhone → Arduino | 3 bytes: joystick X (`int8`, -100 to 100), joystick Y (`int8`), buttons (bit 0 = fire) |
| Feedback | `D00D0002-1F2E-4A3B-8C7D-6E5F4A3B2C1D` | Arduino → iPhone (notify) | 1 byte: 1 = player hit, 2 = demon hit, 3 = demon killed, 4 = game over, 5 = victory |

Service UUID: `D00D0000-1F2E-4A3B-8C7D-6E5F4A3B2C1D`

The iPhone sends the gamepad state 20 times per second when it changes, and every 0.5 s otherwise as a keep-alive.

## Configuration

All game settings are constants at the top of the sketch:

| Setting | Constant | Default |
|---|---|---|
| Column width (higher = faster, more pixelated) | `COL_L` | 4 |
| Wall height | `FACTEUR_HAUTEUR` | 1.3 |
| Player speed / turn speed | `VITESSE` / `VITESSE_ROT` | 3.0 / 2.5 |
| Number of demons | `NB_ENNEMIS` | 6 |
| Shots needed per demon | `VIE_ENNEMI` | 2 |
| Demon speed | `VITESSE_ENNEMI` | 1.3 |
| Demon sight distance | `DISTANCE_VUE` | 8 |
| Damage per attack | `DEGATS` | 10 |

### Editing the map

The level is the 16×16 `CARTE` array in the sketch: `0` is an empty corridor, and `1` to `4` are walls in four different colors. Demon starting positions are in `DEPARTS_ENNEMIS` and must be on empty cells.

## Performance

Expect around **8 to 15 FPS** with an ST7796S display, and less with an ILI9488, which needs 3 bytes per pixel instead of 2. The frame rate drops when a demon fills a large part of the screen. The current FPS is printed to the Serial Monitor at 115200 baud. Increasing `COL_L` to 6 or 8 trades resolution for speed.

## Troubleshooting

| Problem | Fix |
|---|---|
| White screen | Wrong controller selected: toggle `ECRAN_ILI9488`, then check the wiring. |
| Inverted colors | Set `COULEURS_IPS` to `true`. |
| Upside-down image | Set `ROTATION` to `3`. |
| Black screen | Check the LED (backlight) wire. |
| The app stays on "Recherche de l'Arduino…" while the display shows "BLE OK" | Another device or app is connected to the Arduino. Close other BLE apps, then unplug and replug the board. |
| Black screen in the app on launch | The Bluetooth usage description is missing or empty in the **Info** tab. |
| `Build input file cannot be found: ...Bridging-Header.h` | In Build Settings, search `bridging` and clear the **Bridging Header** value. |
